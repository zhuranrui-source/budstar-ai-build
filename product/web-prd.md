# BudStar AI Web 首发 PRD

## 文档定位

本文补充 `product/prd.md`，冻结 Web 首发产品边界和验收口径；旧 PRD 继续保留业务背景与课程细节。首发由 `consumer-web`（官网与星芽星球）和 `admin-web`（员工后台）组成，共用统一 API。ADR-0006～0010 的实现拆解见 `product/upgrade-spec.md`（ISSUE-01～08，含目标与验收标准）。

## 首发目标

- 让访客理解课程价值并完成预约留资。
- 让已授权家庭在封闭的星芽星球查看学生作品、正式点评和成长报告。
- 让校区成员完成班级、提交、点评、报告和预约线索的核心运营。
- 以单校区试点体验上线，同时保证所有校区业务数据具备明确归属和隔离。

## 角色与身份

| 角色       | 登录方式                             | Web 首发能力                                                     |
| ---------- | ------------------------------------ | ---------------------------------------------------------------- |
| 访客       | 无需登录                             | 浏览官网、提交预约线索                                           |
| 家长       | 微信登录 + 手机号绑定                | 与学生共用家庭视图：作品、点评、报告与家庭可见内容               |
| 学生       | 无独立登录（家庭视图内学生档案切换） | 与家长共用家庭视图：课程、作品、反馈和星芽星球授权内容           |
| 教师       | 密码 + 二次验证                      | 班级管理、提交处理、点评与报告发布、家长沟通；数据限授权校区     |
| 合作方     | 密码 + 二次验证                      | 查看已发布课程与活动内容，经营自有生源；不接触学生与线索数据     |
| 平台管理员 | 独立平台身份 + 二次验证              | 平台治理、课程版本、跨校区配置与预约线索跟进；不得伪装为校区成员 |

校区内员工仅保留教师一类（ADR-0009）：原教务/校区管理员职责中，班级管理与报告发布并入教师，线索跟进归平台管理员。校区数据边界不因角色简化放松，服务端仍按校区归属过滤。合作方为 B 端合作机构（我方培训讲师并迭代课程），仅可见内容发布，不得访问未成年人数据、预约线索和校区运营数据。任何用户不得仅凭前端角色声明扩大权限。

## Web 首发范围

### consumer-web

- 官网：品牌、课程体系、适龄人群、学习成果、校区与预约入口。
- 预约表单：家长姓名、手机号、孩子年龄/年级、兴趣课程、校区、期望联系时间。
- 家庭视图（ADR-0007）：家长与学生共用同一视图，微信登录 + 手机号绑定（ADR-0006）；多孩家庭支持学生档案切换，这是档案选择而非角色分流。
- 亲子共学：课节内容家长学生可一起学习；作品提交显式归属学生档案，操作账号记录为协助者，教师端批改与成长评价链路始终认学生档案。
- 家庭视图统一不展示五维数字等级与排名，仅呈现描述性反馈、成长徽章和已发布成长报告；详细评价保留在成长报告中。
- 星芽星球：获得监护人一次性展示授权（ADR-0008，可撤销）的作品默认进入站内公开流，营造开放社区氛围；不被搜索引擎收录。

### admin-web

- 员工登录、二次验证和校区上下文选择。
- 班级、学生与家庭绑定状态查看。
- 作品提交队列、AI 点评草稿、人工编辑与正式发布。
- 五维成长评价复核和成长报告人工发布（教师）。
- 预约线索列表、备注、负责人及完整状态流转（平台管理员）。
- 合作方内容门户：已发布课程包与活动信息，不含学生数据。
- 平台管理员的课程版本治理和必要平台配置。
- 响应式 H5 + PWA（ADR-0010）：教师 / 平台管理员 / 合作方按身份空间路由隔离（/teacher、/platform、/partner），移动端以待办流为核心（待跟进线索、待审核内容、AI 草稿处理、告警），桌面端提供完整导航；/partner 路由预留独立拆分边界。

### API 与平台能力

- 统一身份、校区授权、审计记录、输入校验和访问控制。
- 课程包不可变版本；班级绑定明确版本。
- AI 模型主备路由；对话支持实时响应，失败时可切换备用模型。
- 数据浏览器仅提供受控实体、字段和筛选，不允许任意 SQL。

## 明确不在首发

- 在线支付、合同、发票、退款、优惠券和分账。
- 对互联网公开的社区、匿名互动、公开作品搜索和默认对外分享（星芽星球站内公开流不在此列）。
- 营销自动化、呼叫系统、企微自动触达和投放归因。
- 多校区运营看板、加盟结算和任意跨校区数据导出。
- AI 自动发布点评、评分或成长报告。

## 核心业务规则

1. 单校区首发是界面和运营范围，不是数据模型捷径；校区数据必须带校区归属，服务端按授权校区过滤。
2. 家长只能访问有效家庭绑定下的学生数据；作品公开展示需监护人展示总开关开通（ADR-0008）：家庭绑定或入班时一次性授权，默认展示、可随时撤销、版本化记录，不逐作品审批。
3. 星芽星球站内公开流面向登录用户，不等于对互联网公开：搜索引擎收录（维持 noindex）、匿名互动和公开作品搜索仍不开放；社区内容按风险等级进入自动拦截、人工复核或正常发布流程。
4. 课程包版本一经发布不可修改；修订必须创建新版本，已有班级继续绑定原版本。
5. AI 对话可实时返回，但 AI 点评、五维评价和成长报告只是草稿，必须由授权员工确认发布。
6. 五维固定为问题发现、AI 协作、创意表达、技术实现、迭代反思，每维 1–5 级并附依据；家庭视图统一不显示数字等级。
7. 预约线索可公开创建；手机号应规范化保存、日志脱敏，并限制跨来源滥用。
8. 报名记录是线索转化结果，不等同于支付完成。

## 状态机

### 预约线索

`待联系 → 已联系 → 已预约 → 已到访 → 已报名`

任一未报名状态可转为 `已关闭`；`已关闭` 仅可由有权限员工重新打开到原跟进状态，并记录原因。状态变更须记录操作者、时间和备注。

### 作品提交与点评

- 作品提交：`草稿 → 已提交 → 需修改 → 已重交 → 已完成`
- AI 点评草稿：`未生成 → 生成中 → 已生成 / 生成失败 → 已采用 / 已弃用`
- 正式点评：`草稿 → 已发布`；已发布内容的修订形成新版本并保留历史。

### 五维评价与成长报告

- 五维评价：`待生成 → 已生成 → 待复核 → 已确认`
- 成长报告：`未就绪 → 草稿生成中 → 待人工审核 → 已发布`

AI 失败不得阻塞教师手工完成点评或报告。

### 社区内容

`草稿 → 待审核 → 已发布 / 已拒绝 / 已隐藏`

低风险内容可按策略自动通过；中高风险内容必须人工审核，高风险内容先隐藏再处置。

## 预约线索首条纵向切片

公开接口接收家长姓名、手机号、孩子年龄或年级、兴趣课程、校区、期望联系时间，成功后生成唯一线索并进入 `待联系`。接口返回公开安全字段，不回显完整手机号；重复点击应由客户端禁止，服务端为后续幂等策略保留扩展点。首批可使用明确标注的内存存储，持久化边界须可替换为 PostgreSQL。

consumer-web 必须展示提交中、成功和失败状态，并在失败时保留用户输入。API 必须提供健康检查、白名单 CORS、请求体大小限制、输入校验和脱敏日志。

## 非功能要求

### 安全与隐私

- 不在代码、日志、错误响应或前端包中存放密钥。
- 未成年人数据最小化采集，默认私有；授权、访问与发布操作可审计。
- 中国大陆生产数据部署于腾讯云中国大陆地域；跨境、外部模型传输和公开展示须经合规评估与明确授权。
- CORS 默认只允许配置的 Web 来源；生产环境禁止通配来源。
- 管理员接口必须认证、授权并校验校区范围。

### 质量与可运维性

- 共享契约驱动前后端输入校验，公共行为有自动化测试。
- 健康检查不泄露内部依赖和配置。
- API 错误使用稳定错误码；日志不得记录完整手机号、验证码或未成年人自由文本。
- 本地开发无需 PostgreSQL 即可运行首条切片；切换持久化实现不改变应用服务契约。
- 每个应用提供 lint、format、typecheck、test、build 命令。

### 性能与可用性

- 普通 API 在正常负载下目标 P95 小于 500ms（不含外部 AI）。
- 预约提交失败可安全重试；AI 主模型失败时按策略切换备用模型并明确降级。
- consumer-web 关键公开页面满足移动端可用和基础无障碍要求。
