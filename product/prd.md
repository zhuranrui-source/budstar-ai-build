## 背景与问题

### 背景

BudStar AI 是面向青少年 AI 教育的课程与校区交付体系，核心定位不是复刻豆包爱学的 C 端全学科答疑工具，而是服务校区、品牌合作商、学校/机构、老师、教务、学生和家长的 AI 课程交付平台。

当前业务资料已经形成较清晰的线下/机构运营体系：AI 星芽种子实验班、AIGC 无限创作、Vibe Coding 氛围编程、家长服务 SOP、教学运营 SOP、体验课转化 SOP、招生获客和机构合作 SOP。MVP 需要把这些 SOP 中最核心的课程交付闭环产品化，而不是一开始实现完整 CRM、加盟商管理、支付、合同、营销自动化或总部看板。

### Problem Statement（问题陈述）

BudStar AI 要验证的是：一个校区能否用数字化系统稳定交付一套 16 节主课 + 8 节线上答疑的青少年 AI 创作课程，让学生持续产出作品，让老师低成本点评，让家长看见成果与成长，并自然产生体验课/亲子营/学期课等预约意向。

如果只做学生学习 App，会缺少老师点评、家长信任和校区交付能力；如果一开始做完整校区运营 SaaS，又会被 CRM、支付、营销、加盟和多校区管理拖垮。MVP 必须只验收一条硬闭环。

## 目标与成功指标

- 用户目标: 学生能完成 AI 创作与 Vibe Coding 学习并沉淀作品；家长能看见孩子成果、反馈和成长；老师/教务能低成本完成课程交付和家长沟通。
- 业务目标: 验证 BudStar AI 课程交付闭环能支撑单校区试点，并形成面向中高端家长的可信课程展示和预约入口。
- 项目目标: 交付 Android 学生/家长端 + Web 老师/教务后台 + 统一后端/API/AI 服务层的可扩展 MVP。

### MVP 硬闭环

第一版只验收一条硬闭环：

> 开班 → 学生学习 → 提交作品 → AI/老师点评 → 家长查看 → 阶段报告/作品集沉淀 → 预约咨询留资

### 成功指标

#### 产品闭环指标

- 1 个校区可创建班级并发放班级码。
- 至少 1 个班级可绑定 AI 星芽种子实验班课程包。
- 学生可手机号验证码登录并通过班级码加入班级。
- 学生可完成至少 4 节课学习与作品提交。
- 家长可手机号验证码登录，并通过家庭查看码绑定孩子。
- 家长可查看作品集、每课反馈、阶段报告和课程活动窗口。
- 至少 1 条预约咨询线索可从家长模式提交到 Web 后台。

#### 教学交付指标

- 16 节主课每节都有明确作品提交要求。
- 老师可在 Web 后台查看作品、生成 AI 点评草稿、确认发布正式点评。
- 每课一报同时沉淀为 App 内结构化反馈和可复制微信文案。
- 第 4 节阶段成长报告可生成。
- 五维 AI 自动评分可生成并展示给家长/老师。
- 学生端仅展示成长徽章/能力标签，不展示五维数字分数。

#### 工程交付指标

- Android App 可安装、登录、选择学生/家长模式、加入班级或绑定孩子。
- Web 老师/教务后台可登录并完成核心操作。
- API 有基础自动化测试。
- AI Prompt 有回归测试集。
- Staging 环境可用。
- 核心错误、AI 调用失败、上传失败可记录。
- 数据模型包含 campus_id 或等价校区归属字段，支持未来多校区扩展。

## 用户与场景

### 目标用户

- 学生: 6-15 岁青少年，参加 BudStar AI 课程，在 Android App 中学习、提问、提交作品、查看徽章和作品集。
- 家长: 中高端家长群体，关注孩子是否真正学到 AI 思维、是否有可见成果、课程是否值得持续投入。
- 老师: 负责课堂交付、作品点评、学习反馈、AI 工具指导。
- 教务/班主任: 负责开班、学生跟进、家长沟通、每课一报、阶段报告和轻量预约线索处理。
- 校区/品牌合作商: 负责本地课程交付和试点运营。
- 总部: 负责课程体系、Prompt、评价标准、价格、活动内容等预置配置。

### 使用场景

- 校区开设 AI 星芽种子实验班，教务创建班级并给学生班级码。
- 学生课上或课后打开 App，学习当前主课内容，向星芽 AI 老师提问，提交作品。
- Vibe Coding 阶段学生通过家庭自管 GitHub 仓库提交仓库地址、演示链接和说明。
- 老师在 Web 后台查看作品，基于 AI 点评草稿编辑后发布正式点评。
- 家长打开同一个 Android App，选择我是家长，绑定孩子，查看作品、报告和项目展厅。
- 家长在课程活动窗口查看体验课、亲子营、学期课和透明价格，提交预约咨询。
- 教务在 Web 后台处理预约线索，更新状态和备注。

### 用户故事

- 作为学生，我希望看到自己所在班级的课程进度，并知道每节课要完成什么作品。
- 作为学生，我希望星芽 AI 老师能围绕当前课程帮我拆解任务、优化提示词、解释 GitHub/README/前后端概念，但不直接替我完成作业。
- 作为学生，我希望提交 AIGC 作品或 Vibe Coding 项目后，能看到老师反馈和成长徽章。
- 作为家长，我希望在 App 中看到孩子 16 节课的作品沉淀、老师点评、阶段报告和最终项目。
- 作为家长，我希望清楚了解体验课、亲子营、学期课的课程内容、价格、课时和成果，而不是被低价促销打扰。
- 作为老师，我希望 AI 帮我生成点评草稿，但最终由我确认发布。
- 作为教务/班主任，我希望从后台复制每课一报微信文案，并处理家长预约咨询。

## 范围

### In Scope

- Android App: 首屏角色选择、学生模式、家长模式。
- 学生模式: 手机号验证码登录、班级码加入、课程学习、星芽 AI 老师、作品提交、作品集、成长徽章。
- 家长模式: 手机号验证码登录、家庭查看码绑定、作品集/项目展厅、每课反馈、阶段报告、课程活动窗口、轻量预约留资。
- Web 老师/教务后台: 班级创建、课程分配、学生列表、提交查看、AI 点评草稿、正式点评发布、微信文案复制、阶段报告查看/生成、预约线索处理。
- 课程: AI 星芽种子实验班，16 节主课 + 8 节线上答疑。
- 课程结构: 8 节 AIGC 创作主课 + 8 节 Vibe Coding 主课。
- 作品提交: 每节主课必须有提交；AIGC 支持图片/链接/说明；Vibe Coding 必须支持 GitHub 仓库地址、演示链接或录屏链接、README/说明。
- Vibe Coding: 课程覆盖外部 API、BaaS、模板后端三种服务端能力；最终项目至少使用一种服务端能力。
- AI 能力: 星芽 AI 老师、AI 点评草稿、AI 五维自动评分。
- 报告: 第 4/8/12/16 节阶段成长报告。
- 权限: Student、Parent、Teacher、Academic Service、Campus Admin 基础角色权限。
- 总部能力: 通过预置配置提供课程包、课程内容、答疑模板、Prompt、评价标准、价格和课程活动内容。
- 数据模型: 支持 Campus 归属，但 MVP 界面按单校区试点体验设计。

### Out of Scope

- 全学科拍题答疑、作业批改、作文代写、泛聊天陪伴。
- 独立家长 App、老师 Android App。
- 完整招生 CRM、课程顾问工作台、自动分配顾问、企微集成、呼叫系统。
- App 内支付、合同、发票、退款、优惠券、续费自动化、转介绍积分。
- 总部多校区看板、加盟商管理、城市合伙人权限、分成结算。
- App 内直播、实时音视频、白板、连麦、录制。
- 自动 clone GitHub、自动读取代码、自动 code review、自动跑测试、自动提交 commit。
- 内置 IDE、代码托管、GitHub 深度集成。
- 公开社区、公开作品广场、默认公开项目展示。
- 投放 ROI、营销活动管理、内容日历管理。

### 非目标

- 不做豆包爱学式 C 端全能学习助手。
- 不在 MVP 内验证完整加盟商 SaaS 管理。
- 不通过低价促销和强转化漏斗驱动家长模式。
- 不让 AI 替学生完成最终作品或提交作业。

## 解决方案

### 方案概述

BudStar AI MVP 采用“窄业务闭环 + 可扩展平台底座”方案：

- Android App 服务学生和家长。
- Web 后台服务老师和教务/班主任。
- 后端提供统一 API、Postgres 数据、对象存储和 AI 服务层。
- AI 能力围绕课程交付闭环，而不是泛化问答。
- 总部配置以种子数据、配置文件、脚本或最小内部配置方式实现。

### 主流程

1. 教务/班主任在 Web 后台创建班级，绑定 AI 星芽种子实验班。
2. 系统生成班级码。
3. 学生打开 Android App，选择“我是学生”，手机号验证码登录。
4. 学生输入班级码，填写基础信息后加入班级。
5. 学生查看 16 节主课结构和当前课程任务。
6. 学生使用星芽 AI 老师进行课程内学习和作品辅导。
7. 学生提交作品：AIGC 图片/链接/说明，或 Vibe Coding GitHub 仓库/演示链接/说明。
8. 老师在 Web 后台查看提交，生成 AI 点评草稿。
9. 老师编辑并发布正式点评。
10. 系统沉淀每课反馈、作品集/项目展厅条目和 AI 成长记录。
11. 第 4/8/12/16 节生成阶段成长报告和五维 AI 自动评分。
12. 家长打开 Android App，选择“我是家长”，手机号验证码登录。
13. 家长输入家庭查看码绑定孩子。
14. 家长查看作品集、每课反馈、阶段报告、项目展厅和课程活动窗口。
15. 家长提交体验课/亲子营/学期课预约咨询。
16. 教务/班主任在 Web 后台处理预约线索并更新状态。

### 异常与边界场景

- 班级码无效: 学生端提示检查班级码或联系老师。
- 班级已关闭: 禁止加入，提示联系教务。
- 手机验证码失败: 提示重试；MVP 可先使用 mock 验证码，正式上线需接短信服务。
- 家庭查看码无效/过期: 家长端提示重新向学生或教务获取。
- 作品提交缺少必填项: 禁止提交，提示补充标题、说明、材料链接或图片。
- Vibe Coding 提交缺少 GitHub 仓库地址: 对应用项目类作业禁止提交。
- AI 老师遇到代做请求: 拒绝代做，并转为分步骤引导。
- AI 点评生成失败: 老师可手动填写点评。
- AI 五维评分失败: 报告显示待生成，后台可重试。
- AI 分数明显异常: 老师可标记需复核，但不直接改 AI 分数。
- GitHub 链接无法访问: 系统记录链接；老师人工判断并提醒学生/家长检查权限。
- 线上答疑: 仅记录外部会议链接、主题、摘要和材料，不提供 App 内会议能力。

## 页面与交互

### Android App 页面

- 角色选择页: 选择“我是学生”或“我是家长”。
- 学生登录页: 手机号验证码登录。
- 班级码加入页: 输入班级码、填写姓名/昵称、年龄/年级。
- 学生课程首页: 展示课程包、主课进度、线上答疑入口、当前任务。
- 主课学习页: 图文/步骤/任务/提交要求/AI 老师入口。
- 星芽 AI 老师页: 课程内对话、问题输入、上下文提示、拒绝代做引导。
- 作品提交页: 按课程类型展示提交字段。
- 学生作品集页: 创意作品、应用项目、最终项目展厅、成长徽章。
- 家长登录页: 手机号验证码登录。
- 家庭查看码绑定页: 输入绑定码并绑定孩子。
- 家长首页: 孩子概览、课程进度、最新作品、最新反馈。
- 家长作品集页: 16 节作品、最终项目、老师点评。
- 阶段报告页: 第 4/8/12/16 节报告、五维分数与理由、老师观察。
- 课程活动窗口: 体验课、亲子营、学期课、课程体系、透明价格。
- 预约咨询页: 提交兴趣课程、孩子信息、联系方式、校区、联系时间。

### Web 老师/教务后台页面

- 登录页。
- 工作台首页: 班级、待点评提交、待处理预约、报告节点提醒。
- 班级管理: 创建班级、绑定课程包、生成班级码。
- 学生管理: 查看学生档案、进度、家庭绑定状态。

## 工程实现说明

### 相关系统 / 模块

- Android App: Student Mode + Parent Mode。
- Web Console: Teacher / Academic Service Console。
- API 服务: 统一业务 API。
- 数据库: Postgres。
- 文件/图片: 对象存储。
- AI 服务层: AI 老师、AI 点评草稿、AI 五维评分、Prompt 回归测试。
- 配置/种子数据: 课程包、主课、答疑、评价标准、价格、课程活动窗口。
- CI/CD: Android 构建、Web 构建、API 测试、Prompt 回归测试、staging 部署。

### 现有能力

- 仓库已有 Android 项目结构、Gradle、GitHub Actions、端到端交付相关规划文档。
- 已有豆包爱学探索报告、产品架构资料、BudStar AI 执行手册和 SOP 资料作为需求依据。
- 已有 `CONTEXT.md` 和 ADR 记录本轮确认的领域语言与产品/架构决策。

### 技术约束

- Android 使用 Kotlin + Jetpack Compose。
- Web 后台建议 React / Next.js。
- 后端使用统一 API 服务，推荐 TypeScript + NestJS + Prisma + Postgres，便于与 Web 后台和 AI 服务层共享工程语言与类型。
- 数据模型需要 campus_id 或等价校区归属字段。
- MVP 支持多校区数据模型，但界面按单校区试点体验。
- GitHub 使用外部工作流，平台只记录仓库 URL 和说明，不管理 GitHub 账号，不 clone 代码。
- 线上答疑使用外部会议工具链接，不做 App 内会议能力。
- AI 生成内容需要 Prompt 策略、回归测试和失败兜底。
- 手机号验证码正式上线需短信服务；MVP 内测可使用 mock 验证码。

### 测试切面

- Android: 登录、角色选择、班级码加入、课程查看、提交作品、家长绑定、家长查看报告、预约提交。
- Web: 创建班级、查看提交、生成 AI 点评草稿、发布点评、复制微信文案、生成报告、处理预约线索。
- API: 核心对象 CRUD、权限隔离、状态流转、campus 数据归属。
- AI: 课程内问答、拒绝代做、点评草稿、五维评分、异常输入、敏感内容。
- 数据: 家长只能查看绑定孩子；老师/教务只能查看所属校区数据。
- 文件/链接: 图片上传、作品链接、GitHub URL 格式、演示链接。
- 回归: Prompt 变更必须跑 AI 测试集。

### 灰度方案

- 先在 1 个试点校区、1 个班级内测。
- 先使用测试账号/mock 验证码验证流程，再接入真实短信服务。
- AI 老师和 AI 点评保留开关，异常时可关闭 AI 生成功能，保留手动点评。
- 线上答疑使用外部会议工具，不影响 App 主流程。

### 回滚预案

- AI 点评失败时回退到老师手动点评。
- AI 五维评分失败时报告显示待生成，允许后台重试。
- 家长预约失败时提示稍后重试并记录错误。
- 上传失败时保留草稿并提示重新提交。

### 上线监控

- 登录失败率。

| 合规风险 | 学生 GitHub 账号由家庭自管，涉及平台年龄和监护人责任 | 可能引发账号注册和隐私问题 | App 内提示由家长/监护人负责账号注册、保管和授权；平台只记录 URL |
| 合规风险 | 学生作品、照片、GitHub 链接和报告涉及未成年人隐私 | 对外展示风险高 | 默认受控展示；外部宣传需家长授权和老师审核 |

| 工程风险 | 过早做总部/多校区/CRM 会拖慢 MVP | 影响交付 | 按 ADR 严格控制 Out of Scope |
